# work-tree-sync

该仓库是**单快照同步**，不是版本管理：每次上传都把全部文件压成一条全新的根提交并强推，远端历史永远只有 1 条。不要用常规 git 流程，一切走仓库根目录的 `sync.sh`。

## 执行时机（硬约束）

- **不要自动执行 `up` 或 `down`。** 修改、新增、删除文件之后，只做本地改动并汇报结果，不推送、不拉取。
- 只有用户明确说出"更新到远端 / 推送 / 传上去 / 传到 git"这类指令时，才执行 `sync.sh up`。
- 只有用户明确说出"从远端同步 / 拉下来 / 更新下来 / 电脑 B 的改动拉过来"这类指令时，才执行 `sync.sh down`。
- 用户没说清楚是指令还是描述时，先问一句再动手。
- 同理，不要在该仓库执行任何隐式的 `git push`、`git pull`。

## 两次确认

脚本的每个写操作（`up` 推送、`down` 覆盖本地、`install-skills.sh` 覆盖本机技能）都要连问两次，两次都答 `y` 才执行。执行时：

- 不代替用户回答，不复述成"已确认"，把两次提示原样交给用户。
- 用户只答了一次就等待，不要自动补第二次。
- 两次都没答完即视为取消，不要重试命令。

## 命令选择

| 用户意图 | 命令 |
|---|---|
| 把本地改动传到远端 | `./sync.sh up` |
| 把远端最新内容拉到本地（并同步技能） | `./sync.sh down` |

```bash
cd ~/Desktop/my_work_tree
./sync.sh up     # 本地 -> Git
./sync.sh down   # Git -> 本地，随后自动安装 .skills/ 下的技能
```

其他机器上的仓库路径以实际 clone 位置为准，命令相同。

## 脚本已内置行为，不要手工重复

- `up`：`git add -A` → `commit-tree` 生成无父提交 → `update-ref` → `push --force` → `reflog expire` + `gc --prune=now`。提交号每次都会变，属预期现象。
- `up` 在"远端自本机上次同步后被别的机器更新过"时停下来要求确认；此确认必须由用户回答，不要代答 `y`。
- `down`：`reset --hard` 对齐远端；仅当本地有未提交改动或远端没有的提交时才要求确认。
- `down` 成功后自动调用 `install-skills.sh`，把 `.skills/*` 安装到本机技能目录。已有 `.installed-by` 标记指向本仓库的同名技能会被整体覆盖；没有标记或标记来自其他仓库的同名技能会被跳过，避免误删与本项目无关的技能，需要接管时用 `./install-skills.sh --force`。
- 文件内容与远端一致时，`up` 直接判定"无改动"退出，不产生新提交。

## 技能目录约定

- 技能放在仓库根的 `.skills/<技能名>/SKILL.md`，`.skills` 这一层保持扁平，一个技能一个目录。
- 领域归类用目录名前缀（`eb-`、`rc-`、`xhs-`），不要建多级嵌套，避免装进本机后重名互相覆盖。
- 技能名不要与豆包自带技能重名（`pdf`、`sheet`、`docx`、`word`、`ppt`、`html` 等），同名时无法判断最终哪个生效；一律加项目前缀。
- 技能内部可以有 `scripts/`、`references/`、`assets/` 子目录，属于技能自身资源。
- 业务素材、商品图、导出数据放 `data/`，与 `.skills/` 一样随 git 快照同步；技能里用相对路径引用。
- 修改技能以工程内文件为准；直接改本机已安装副本会在下次 `down` 时被覆盖。

## 硬性约束

1. 不要在该仓库执行 `git commit`、`git push`、`git pull`、`git merge`、`git rebase`，也不要手工 `git reset` 后自行推送——一律走 `sync.sh`。
2. 不要为"保留历史"另建分支或备份；用户明确要求只保留一份快照。
3. `data/` 随仓库一起同步；仅 `.DS_Store`、`*.tmp` 被忽略。单个超大文件单独评估，避免每次 `up` 全量重传。
4. `up` 是向远端写入，运行前确认用户确实要求上传。

## 故障排查

| 现象 | 处理 |
|---|---|
| `拉取远端信息失败` | 检查网络与 SSH key：`ssh -T git@github.com` |
| `推送失败` | 重跑一次；连续失败再查远端权限或分支保护 |
| 远端多出提交（历史被污染） | 跑一次 `./sync.sh up` 即可压回 1 条 |
| 技能没生效 | 确认 `down` 后重开一轮会话；或手动执行 `./install-skills.sh` |
| 需要确认远端现状 | `git ls-remote origin`、`git --git-dir=.git ls-tree --name-only origin/main` |
